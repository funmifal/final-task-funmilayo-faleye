Rota — Enterprise Workforce Scheduling & Sub-Millisecond Redis Feed

Multi-tenant workforce mobile application engineered with offline synchronization, double-entry financial ledger, and high-performance cursor pagination.

GitHub Repo → Load Test Report

The Engineering Challenge

In high-velocity enterprise workforce environments, hundreds of employees simultaneously request activity updates and shift assignments during shift changeovers. Standard relational database queries with traditional offset pagination caused database connection pool exhaustion and spiking latency as the activity log exceeded millions of rows.

The Architectural Solution

Engineered a 3-tier client/server architecture combining React Native, Express BFF, and Redis read-through caching with keyspace cursor pagination. Implemented TanStack Query for server state cache invalidation, Zustand for lightweight client state, and AsyncStorage for seamless offline resilience. Subscription billing was built using integer-cents deterministic proration and a double-entry ledger.

Matinee — High-Concurrency Cinema Booking & The "Zainab & Musa" Solution

Mobile cinema ticket booking platform built with atomic Redis seat locking, database unique constraints, and high-fidelity interactive seat map.

GitHub Repo → Traffic & Locking Spec

The "Zainab & Musa" Concurrency Problem

During high-demand movie premiere ticket drops, thousands of cinema goers attempt to reserve the same optimal seats at the exact same millisecond. If user Zainab and user Musa both select Seat F14 simultaneously, standard relational queries without distributed locks create race conditions, double charging customers and producing duplicate bookings.

The Multi-Layered Defense

Designed a two-phase seat reservation system. First, atomic Redis locks using SET seat:{id}:lock {user_id} NX EX 600 hold the seat for 10 minutes with zero database load. If checkout completes, a PostgreSQL composite unique constraint (showtime_id, seat_id) provides an immutable safety net. If payment fails or times out, the Redis key expires automatically, releasing the seat instantly without human intervention.

Background Job System — Resilient Distributed Queue & Crash Recovery

Asynchronous background processing architecture for AI customer review analysis featuring worker concurrency limits, automatic crash recovery, and dead-letter queues.

GitHub Repo → 13 Execution Artifacts

The Distributed Processing Challenge

In high-volume AI review ingestion systems, external LLM endpoints frequently time out, worker nodes crash mid-execution, and clients submit duplicate review batches. Without durable queue semantics, jobs are either dropped permanently, executed multiple times (wasting expensive API tokens), or left in an orphaned "in-progress" state forever.

The Resilient Architecture

Engineered a distributed Node.js/TypeScript queue service built on Redis sorted sets and pub/sub. Every incoming payload is fingerprinted with an SHA-256 hash to enforce exact-once idempotency. Built a heartbeat monitor that reclaims stalled jobs if a worker node crashes ungracefully. Failed jobs undergo exponential backoff retries with random jitter before routing to an operator-accessible Dead Letter Queue (DLQ).
